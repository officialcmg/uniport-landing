## Your setup, found before any request

The button checks what you pass it before it asks the API for anything. If something is wrong, nothing throws and your page keeps working:

- `UniportButton` renders disabled.
- `UniportModal`, used on its own, shows “Payment unavailable”.
- The console says what to change.
- `onError` is called once.

<DocTable
  head={["code", "Cause"]}
  rows={[
    [<M>MISSING_RECIPIENT</M>, <><C>recipient</C> is missing or empty.</>],
    [<M>INVALID_RECIPIENT</M>, <><C>recipient</C> has spaces around it, or on an EVM chain is not <C>0x</C> and 40 hex characters.</>],
    [<M>INVALID_DESTINATION_TOKEN</M>, <><C>destinationToken</C> is missing or is not a <a className="d-link" href="/docs/chains-and-tokens">supported token name</a>.</>],
    [<M>INVALID_AMOUNT</M>, <><C>amount</C> is set but is not a string holding a positive number, or has more decimals than the token.</>],
    [<M>SECRET_KEY_AS_APP_ID</M>, <>A secret key was passed as <C>appId</C>. It is never sent.</>],
    [<M>APP_ID_REQUIRED</M>, <>The site isn’t <C>localhost</C> and no <C>appId</C> was passed. Create an app in the <a className="d-link" href="/dashboard">dashboard</a>.</>],
  ]}
/>

To run the same check yourself, for example before showing your own button:

<Code
  file="check.ts"
  lang="ts"
  code={`import { checkPaymentSetup } from "uniport-sdk";

const problem = checkPaymentSetup({
  recipient,
  destinationToken,
  amount,
  appId,
  hostname: window.location.hostname, // needed to report APP_ID_REQUIRED
});
if (problem) console.log(problem.code, problem.details);`}
/>
